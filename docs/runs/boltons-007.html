The bug is in the logic that appends the extension when generating kept_names. When fn_ext is empty (i.e., the filename has no extension), the code incorrectly appends the extension (which is empty) after the number, but when fn_ext is not empty, it should still include the extension in the filename. The current condition uses `if not (fn_ext)` which is truthy when fn_ext is an empty string, but the logic for appending the extension is reversed. The fix ensures that the extension is always included in the generated filename, regardless of whether it exists.
